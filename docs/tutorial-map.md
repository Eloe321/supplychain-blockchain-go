# Mapping Jeiwan's seven tutorials to this application

Ivan Kuznetsov's series provides the learning progression. This repository contains original implementation code and does not reproduce large tutorial snippets. The linked posts are attributed educational references; their site lists its own content license.

| Reference | Learning concept | Application code and deliberate adaptation |
| --- | --- | --- |
| [Part 1: Basic Prototype](https://jeiwan.net/posts/building-blockchain-in-go-part-1/) | Linked blocks, hashing and genesis | `ledger/block.go` defines explicit versioned headers and a deterministic configuration-derived genesis; `chain/chain.go` retains a block graph and canonical path instead of an in-memory string-data chain. |
| [Part 2: Proof-of-Work](https://jeiwan.net/posts/building-blockchain-in-go-part-2/) | Nonce search and cheaply verified SHA-256 proof | `ledger/block.go` mines and verifies custom fixed-difficulty proof using cancellable contexts. `chain/chain.go` chooses cumulative work with a deterministic hash tie rule. This is a custom educational protocol, not Bitcoin-compatible mining. |
| [Part 3: Persistence and CLI](https://jeiwan.net/posts/building-blockchain-in-go-part-3/) | Persistent blocks and command-line operations | `chain/store.go` uses maintained bbolt with replay validation and atomic canonical-tip updates. `cmd/supplychain/main.go` supplies local key/config/signing and API commands; the running process owns its DB. JSON replaces the tutorial's gob encoding. |
| [Part 4: Transactions 1](https://jeiwan.net/posts/building-blockchain-in-go-part-4/) | Structured records and derived state | `ledger/event.go`, `ledger/state.go` and `chain/mempool.go` replace monetary transactions and spent outputs with signed supply-chain events and whole-batch custody. There are no balances, inputs/outputs, coinbase rewards or UTXOs. |
| [Part 5: Addresses](https://jeiwan.net/posts/building-blockchain-in-go-part-5/) | Public/private keys and actor identity | `ledger/identity.go` uses Ed25519 and SHA-256 public-key IDs rather than Bitcoin ECDSA/Base58 addresses. `ledger/config.go` enrolls public participants. CLI private keys are local 0600 files; `node/identity.go` separately manages libp2p peer keys. |
| [Part 6: Transactions 2](https://jeiwan.net/posts/building-blockchain-in-go-part-6/) | Signatures, indexed state and Merkle commitments | `ledger/event.go` domain-separates fixed-field signing bytes; `ledger/state.go` enforces owner/recipient/sequence rules; `ledger/block.go` commits ordered signed events through a Merkle root. `chain/query.go` exposes canonical custody state and confirmation-bearing traces instead of a UTXO index. |
| [Part 7: Network](https://jeiwan.net/posts/building-blockchain-in-go-part-7/) | Peer messages, transaction propagation and synchronization | `node/` implements encrypted libp2p TCP, strict network/config/genesis handshakes, GossipSub, bounded multi-pass sync, fork validation, peer exchange/reconnects, scoped DHT/mDNS and optional relays. The tutorial's designated central-node workflow is replaced by independent validating peers. `cmd/demo/` demonstrates three actual processes and operation after bootstrap loss. |

A useful reading order is identity/configuration → signed events and state → block proof/Merkle commitments → persistent fork choice → P2P → API/CLI/demo. The supply-chain rules intentionally add a recipient-signed acceptance step: an owner can offer custody, while the enrolled recipient must accept before ownership changes. Reorganizations can revise the canonical trace, so confirmations express depth rather than finality.
